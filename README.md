# 대.세.는 소개팅

> 대전 · 세종을 중심으로 운영하는 프라이빗 소개팅 매칭 서비스

**대.세.는 소개팅**은 많은 사람을 탐색하고 오래 채팅하는 데이팅 앱보다,
운영자가 직접 신청자를 확인하고 서로 어울릴 가능성이 있는 두 사람의
실제 만남을 연결하는 것을 목표로 하는 프로젝트입니다.

현재는 대전·세종 지역의 소규모 운영을 전제로 한 MVP를 개발하고 있습니다.


## 서비스 소개

서비스의 기본 흐름은 단순합니다.

**신청 → 확인 → 제안 → 수락 → 만남**

1. 사용자가 자신의 기본 정보와 원하는 상대 조건을 작성합니다.
2. 운영자가 신청서와 프로필 사진을 직접 확인합니다.
3. 서로의 조건을 고려해 소개 후보를 선정합니다.
4. 양쪽 모두 소개를 원할 경우 만남을 진행합니다.
5. 실제 만남 이후 서로 연락을 이어갈 의사가 있을 때 연락처를 전달합니다.

채팅 기능에서 벗어나 **실제 만남까지 연결하는 것**을 서비스의 핵심 가치로 두고 있습니다.


## 핵심 특징

### 대전 · 세종 중심

전국 단위로 회원 수를 늘리기보다
실제로 만나기 쉬운 대전·세종 생활권에 집중합니다.

### 운영자 직접 매칭

사용자가 수많은 프로필을 직접 탐색하는 방식이 아니라,
운영자가 신청 내용과 조건을 확인한 뒤 소개를 제안합니다.

### 채팅보다 실제 만남

서비스 내부 채팅을 제공하지 않습니다.

소개가 성사되면 실제 장소에서 먼저 만나고,
만남 이후 양쪽 모두 원할 경우 연락처를 교환하는 방식을 목표로 합니다.

### 프로필 카드

신청한 정보를 바탕으로 서비스에서 사용하는 Profile Card가 생성됩니다.

이 카드는 현재 본인 프로필 미리보기에서 사용하며,
향후 상대방에게 전달되는 Match Proposal에도 활용할 예정입니다.


## 현재 개발 상태

현재 프로젝트는 **신청 접수 시스템을 실제 운영 가능한 형태로 연결하는 단계**입니다.

### 구현 완료 / 진행 중

- 메인 랜딩 페이지
- 소개 신청 Form
- 대전·세종 지역 선택
- 프로필 사진 등록 및 구도 조정
- Profile Card 미리보기
- 입력값 검증
- Supabase 기반 신청 데이터 구조
- 프로필 사진 비공개 Storage 구조
- 관리자 로그인 구조
- 신청자 목록 및 상세 확인
- 신청 승인 / 미승인 처리
- 관리자 메모
- 신청 정보 삭제 처리

### 현재 확인 중

- 실제 Supabase 프로젝트와 전체 접수 흐름 연결
- Cloudflare Turnstile 적용
- 실제 신청 → 관리자 확인 → 승인 → 삭제 E2E 테스트
- 개인정보 수집 및 이용 문서 확정


## 프로젝트 발전 과정

### 1. 소개팅 서비스 프로토타입

프로젝트는 처음 **'잘되면 밥한끼'**라는 이름의
간단한 소개팅 서비스 프로토타입으로 시작했습니다.

초기에는 어떤 기능을 제공할 것인지보다
소개팅 서비스를 직접 만들어보는 것이 첫 번째 목표였습니다.


### 2. 매칭 방식 실험

프로젝트를 발전시키며
취향과 연애 가치관을 구분하는 Love Color,
다양한 가입 절차와 매칭 기준 등을 실험했습니다.

하지만 기능과 조건을 계속 추가하는 방식으로는
실제 운영이 가능한 서비스까지 도달하기 어렵다고 판단했습니다.


### 3. 서비스 범위 축소

초창기에 설계했던 구조는 전국 단위 무료 매칭 (개인 도네이션 방식) 서비스로 계획,
피드백 + 여러 소개팅 사이트 및 운영중인 앱과 비교 했을 때 큰 차별성을 가지지 못하는 점 등을 고려하여
비슷한 전국 단위 프리미엄 소개팅 서비스와 경쟁하기보다

**'대전과 세종에서 실제로 만날 사람을 연결한다'**

는 문제에 집중하기 시작했습니다.

이 과정에서 서비스 이름도
**'대.세.는 소개팅'**으로 변경했습니다.


### 4. 실제 만남 중심 MVP

서비스의 핵심 프로세스를

**신청 → 확인 → 제안 → 수락 → 만남**

으로 단순화했습니다.

회원용 채팅, 추천 알고리즘, 복잡한 등급 시스템 등은 MVP에서 제외하고
운영자가 직접 소개를 관리하는 방식으로 방향을 전환했습니다.


### 5. 데이터 기반 운영 구조

프론트엔드만 존재하던 프로젝트에
Supabase를 이용한 데이터 저장 구조를 추가하고 있습니다.

현재는 신청 정보, 연락처, 개인정보 동의,
프로필 사진, 관리자 검토 상태 등을 분리하여 관리하고 있으며
관리자 화면에서 신청자를 확인하고 심사할 수 있는 구조를 구축하고 있습니다.
