개인정보처리방침

대.세.는 소개팅은 소개 신청 및 매칭 운영에 필요한 개인정보를 수집하며, 이용자가 자신의 정보가 어떻게 이용되고 관리되는지 쉽게 확인할 수 있도록 개인정보처리방침을 공개합니다.

개인정보는 소개 신청 심사, 매칭 후보 선정 및 실제 만남 운영을 위해 사용하며, 관계 법령과 운영정책에 따라 관리합니다.

실제 접수 개방 전 안내 아래 보유정책은 확정된 운영 기준입니다. 보유기간에 따른 자동 파기는 아직 구현되지 않았으며, 구현 및 검증 후 실제 운영 접수를 개방합니다.

3. 선택 민감정보: 종교

종교는 상대 선호 및 매칭 참고 목적으로, 별도의 민감정보 수집·이용 동의를 한 경우에만 저장합니다. 동의하지 않아도 신청할 수 있습니다. 미동의 시 브라우저가 전송 항목에서 제외하고 서버도 종교 값을 제거하여 DB에 저장하지 않습니다.

종교 정보에도 아래 4항의 보유·파기 기준이 적용됩니다. 신청 동의만으로 종교 정보를 상대방에게 제공하지 않습니다.

4. 심사 및 보유·이용기간

다음은 각각 다른 시점에서 시작하는 운영 기준입니다. 심사 기한과 보유·파기 기한을 서로 대체하지 않습니다.

A. 신청 심사
신청 접수 후 최대 48시간 이내 심사를 완료하는 것을 운영 기준으로 합니다.
B. 장기 미처리 신청
심사가 완료되지 않은 신청 정보와 프로필 사진도 접수일로부터 30일을 초과하여 보관하지 않습니다. 30일은 심사를 미룰 수 있는 기간이 아닙니다.
C. 미승인 신청자
심사 결과 안내 후 48시간 이내 개인정보와 프로필 사진을 파기합니다.
D. 승인 회원
서비스 이용 종료 또는 개인정보 삭제 요청 후 48시간 이내 개인정보와 프로필 사진을 파기합니다.
E. 법령에 따른 보존
관계 법령에서 별도의 보존 의무가 발생하는 경우에는 해당 법령에서 정한 기간 동안 보관할 수 있습니다.

5. 파기 방법 및 현재 구현 상태

전자적 개인정보는 보유기간이 종료되거나 처리 목적이 달성되면 DB에서 삭제하고, 프로필 사진도 Supabase Storage에서 삭제하는 구조를 사용합니다.

현재 관리자 삭제 기능은 신청 정보와 연결된 연락처·동의·종교·검토 기록 등을 DB 트랜잭션으로 삭제하면서 사진 경로를 삭제 대기열에 남깁니다. 이후 Storage API로 사진을 삭제하고 성공한 대기 기록을 지웁니다. 사진 삭제 실패 시 대기열에 유지되며 관리자가 재시도합니다. DB 삭제와 실제 사진 삭제는 하나의 원자적 작업이 아니므로 동시에 즉시 완료된다고 보장하지 않습니다.

보유기간에 따른 자동 파기는 미구현입니다. 결과 안내 후 48시간, 승인 회원 종료·삭제 요청 후 48시간, 미처리 신청의 접수일 기준 30일 기한을 자동으로 실행하는 정기 작업은 아직 없습니다. 현재의 미완료 업로드 정리 기능은 이 자동 파기를 대신하지 않습니다. 확정된 보유정책에 맞는 자동 파기 구현 및 검증 후 실제 운영 접수를 개방합니다.

외부 서비스의 백업·로그 보유기간과 삭제 처리 방식은 실제 운영 전에 확인하여 안내를 보완할 예정입니다.

6. 개인정보 제3자 제공

현재 대.세.는 소개팅은 신청자의 개인정보를 소개 상대방에게 자동으로 제공하지 않습니다. 신청 화면의 프로필 카드는 본인 확인용 미리보기이며, 상대방에게 전송하는 기능은 아직 구현되지 않았습니다.

향후 특정 상대에게 프로필 정보를 전달할 경우에는 제공받는 사람, 제공 목적, 제공 항목, 보유 및 이용기간, 동의 거부권과 거부에 따른 영향을 사전에 안내하고 별도의 제3자 제공 동의를 받은 후 제공할 예정입니다. 현재의 신청 동의를 향후 상대방 프로필 제공 동의로 간주하지 않습니다.

8. 외부 서비스와 데이터 처리

Supabase
브라우저의 신청 데이터와 구도 조정한 사진을 Edge Functions가 검증하고 PostgreSQL DB와 비공개 Storage에 저장하는 구조입니다. 관리자 로그인은 Auth를 사용하고, 관리자 API가 권한을 확인한 후 신청 조회·검토·사진 임시 URL·삭제를 처리합니다. 신청자용 Auth 로그인은 현재 제공하지 않습니다.
Cloudflare Turnstile
신청 접수가 열리면 브라우저에서 자동입력·봇 방지 위젯을 불러오고 확인 토큰을 서버에서 검증하는 구조입니다. 위젯의 접속 관련 신호가 Cloudflare에서 처리될 수 있습니다. 현재 접수가 닫힌 상태에서는 신청 페이지가 위젯을 불러오지 않습니다. 서버 검증 요청에는 확인 토큰과 서버 전용 키를 사용하며 신청서와 사진을 보내지 않습니다.
Vercel
HTML·CSS·JavaScript·이미지 등 정적 웹사이트를 제공합니다. 현재 코드의 신청 데이터·사진 전송 대상은 Supabase API이며, Vercel의 별도 신청 저장 API를 사용하지 않습니다. 웹페이지 요청 과정의 접속 정보·호스팅 로그 처리와 신청 DB 저장은 구분됩니다.

이 설명은 코드의 역할과 데이터 흐름에 관한 안내입니다. 처리위탁·국외이전 해당 여부, 구체적인 이전 국가·보유기간 및 계약 조건은 실제 운영 전 계약 및 실제 데이터 흐름 확인이 필요하며, 확인 후 공개 안내를 보완합니다.

9. 개인정보 보호를 위한 현재 조치

현재 코드와 스키마에는 다음 조치가 구현되어 있습니다. 실제 배포 환경의 권한·사진 비공개·인증·봇 방지 동작에 대한 통합 검증은 접수 개방 전에 별도로 완료해야 합니다.

  • 앱 테이블의 RLS 활성화와 일반 방문자·일반 로그인 계정의 DB 직접 접근 권한 제한
  • 프로필 사진 비공개 Storage와 관리자용 임시 사진 URL
  • 서버 전용 Secret을 브라우저 코드에 넣지 않는 서버 경유 처리
  • Auth 인증과 허용된 관리자 목록을 함께 확인하는 권한 분리
  • 서버 측 필수 항목·동의·사진 형식 검증 및 접속 주소 기반 요청 제한
  • 접수 개방 시 Turnstile 토큰 검증 조건 적용

사진 형식 검사는 얼굴 본인인증이 아닙니다. 정면 얼굴 여부는 관리자가 심사하며, PASS 인증이나 자동 얼굴 판별이 완료된 것으로 표시하지 않습니다.
